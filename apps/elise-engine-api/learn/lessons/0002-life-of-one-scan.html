The life of one scan

About 7 minutes. Before this: lesson 1.

Your win: after this lesson, you can put the steps of one scan in the correct order.

The request

A scan starts with one HTTP request:

POST /scans
authorization: Bearer <SCAN_API_TOKEN>
{ "repo": "https://github.com/owner/name", "skill": "lite", "effort": "low" }

Only repo is required. The other fields have defaults. The Worker rejects values that are not on its lists (model, effort, skill, profile). It also rejects a repo URL that is not a public GitHub URL.

Three details that matter

The scan ID is the sandbox name

The Worker makes a random UUID (the scan ID). It calls env.SANDBOX.getByName(scanId). The same name always gives the same Durable Object. A new UUID gives a new, empty sandbox.

The agent runs in the background

The Durable Object does not wait for the agent output. It starts the agent as a detached run. The agent writes its output to agent.log. When it ends, it writes its exit code to agent.exit. The Durable Object looks for that file every 5 seconds. Cloudflare’s own coding-agent example uses the same pattern for long runs.

Cleanup always runs

Step 9 is in a finally block. The container is destroyed if the scan works, and also if it fails. See scan().

Check your memory

What is the name of the sandbox?

The scan ID names the sandbox and the folder in R2 (scans/<id>/).

Why does the Durable Object look for agent.exit?

The agent runs in the background. The exit file is the signal that it has ended, and it holds the exit code.

Which step comes first inside the container?

The agent needs the code, so the clone comes first. Reading the report and destroying the container come last.

Wait, what? Re-pitch this lesson

Context. One scan is one HTTP request that ends with a saved report.

Short version. The Worker makes a scan ID and starts a sandbox with that name. The container clones the repo and runs the agent in the background. The Durable Object waits for the exit file, reads the report, and destroys the container. The Worker saves the files to R2.

Remember. Clone, run, wait, read, destroy, save.
