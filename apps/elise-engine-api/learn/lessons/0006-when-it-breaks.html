When it breaks

About 8 minutes. Before this: lesson 5.

Your win: after this lesson, you can find which stage of a scan failed by using the logs and the container list.

Why this lesson exists

Our first scans hung. They gave no error. We lost time because we could not see inside the container. The story below is real. Learn the method, not only the fix.

The story

#What we didResultWhat we learned
1Waited for the agent output directly.Hung, no response.We guessed that helper processes kept the output stream open. We did not prove it.
2Switched to a detached run with file polling.Still hung.We kept it, because the official example uses it. But it did not fix the hang.
3Added a debug route that returns at once.The container was gone: "exec() cannot be called on a container that is not running".The container itself was failing. The size was the likely cause.
4Set standard-1.The agent ran and returned: "Credit balance is too low".A real, readable error. The hang was gone.
5Added Anthropic credit.The scan finished and saved the report.The whole pipeline works.

The method

Follow the stages of a scan. Find the last stage that worked.

The tools

# live logs of the Worker (only shows new requests)
pnpm exec wrangler tail

# list container apps, then the instances of one app
pnpm exec wrangler containers list
pnpm exec wrangler containers instances <ID>

# are reports saved?
pnpm exec wrangler r2 bucket info repo-scan-reports

Run them in apps/elise-engine-api. wrangler tail shows a request only after it ends. A long request can look silent. Wait for the request to end or cancel before you decide there is nothing.

Rules we learned

  1. Make failures visible. A failed scan returns the last 2 KB of the agent log.
  2. Change one thing at a time. We changed the run pattern first. The size was the real cause. Two changes at once would have hidden that.
  3. Build a tiny test. A 60-second test with one word as the prompt told us more than a 10-minute scan.
  4. Read the limits table. It showed that the default size has 256 MiB of memory.

Check your memory

Which command shows live Worker logs?

wrangler tail streams logs. Remember it shows a request only after the request ends.

You see clone requests but no Anthropic requests. Where is the problem?

The clone worked, so the token, the start, and the repo URL are fine. The agent did not reach the model.

We changed two things before the fix worked. What is the lesson?

Single changes show which change has an effect. The size was the fix, and the run pattern was not.

Wait, what? Re-pitch this lesson

Context. Our first scans hung with no error.

Short version. Find the last stage that worked: request, clone, model call, result. Use wrangler tail and the container list. Make the failure show its own error text. Change one thing at a time.

Remember. A silent hang is a lack of information. Add information first.

Primary source: Cloudflare Containers: limits (the table that showed the memory of each type). For Claude Code exit codes, see the print mode guide: a failed run exits non-zero.
