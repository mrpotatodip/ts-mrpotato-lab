Reading a report

About 8 minutes. Before this: lesson 6.

Your win: after this lesson, you can read a scan report, say which findings need a human check, and say what an empty report does not prove.

The two files

The lite skill writes two files into /workspace/out. The Worker saves both in R2 under scans/<scan ID>/.

  • REPORT.md is for people. It has a fixed list of sections: Summary, Findings, Needs validation, Coverage, Limits.
  • findings.json is for programs. It is a JSON array of findings.

The Worker also writes status.json (the repo, the settings, the times, and whether the scan worked). The full skill writes more files, for example coverage-ledger.json.

To read a saved file: GET /scans/<id> returns the report. GET /scans/<id>/findings.json returns the JSON. Both need the bearer token.

One finding

{
  "id": "F-001",
  "status": "confirmed",          // or "needs_validation"
  "severity": "medium",           // null when needs_validation
  "title": "short title",
  "class": "authz",
  "location": [{ "file": "src/routes/user.ts", "line": 42 }],
  "actor": "who exploits it",
  "impact": "the concrete result",
  "evidence": "code and the traced path",
  "fix": "the smallest source change",
  "needs": null                   // the missing fact, when needs_validation
}

Severity has five levels: critical, high, medium, low, informational. A needs_validation finding has no severity. It means that the answer depends on a fact outside the repo, for example a cloud setting.

Two rules for reading

1. An agent finding is a lead, not a fact

The status confirmed means that the agent traced the code and believes the problem is real. It does not mean a person checked. Before you fix a finding, open the file at the location and follow the evidence. Ask: can the named actor really do this?

2. No findings does not mean safe

Our first test scanned a repo that had only a one-line README. The report said "no findings". That was correct, because there was no code. A report for a big project with no findings could also mean that the agent missed things. Always read the Coverage and Limits sections. They say which classes the agent searched and how many files it read.

Check your memory

A report has no findings. What does that tell you?

It says only what the agent found. Read Coverage and Limits to see what it checked.

Which finding status has no severity?

The answer depends on a fact outside the repo, so the agent cannot rate it.

Who must check a finding before you fix it?

The agent can be wrong in both directions: it can report false problems and miss real ones.

Wait, what? Re-pitch this lesson

Context. The scan ends with a report that the agent wrote.

Short version. Read REPORT.md for people and findings.json for programs. Each finding has a status, a severity, a location, and a fix. A person must check each finding. An empty list does not prove safety.

Remember. Lead, not fact. Read Coverage and Limits.
