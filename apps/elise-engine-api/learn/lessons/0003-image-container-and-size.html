Image, container, and size

About 7 minutes. Before this: lesson 2.

Your win: after this lesson, you can explain the difference between an image and a container, say when you need Docker, and say why the container size matters.

Image and container

The image is a frozen file system. It holds Linux, git, ripgrep, Claude Code, and our two skills. You write it in the Dockerfile.

The container is a running machine that starts from the image. Each scan starts a new container from the same image. When the scan ends, the container is destroyed. The image stays.

You build the image again only when the Dockerfile or the skills/ folders change. A change to the Worker code alone does not change the image.

The size problem

Cloudflare gives each container an instance type. The type sets vCPU, memory, and disk. We did not set one at first, so the container used the smallest type, lite.

What we saw, and what we did not prove

  • With lite (256 MiB), the scan hung three times. git clone worked. Claude Code started, then went silent.
  • We set instance: "standard-1" (4 GiB). The next scan finished.

We think the cause is memory, because Claude Code is a Node program and 256 MiB is small. We did not measure memory use. The size change fixed the problem, but a log line that says "out of memory" would prove it. Say "probable cause" until you have that proof.

Check your memory

When do you need Docker (or Colima) on your laptop?

The build happens during wrangler deploy. After that, Cloudflare runs the containers.

Which change made the hanging scan finish?

We deployed the detached run first and the scan still hung. The scan finished after we set standard-1.

How much memory does the lite type have?

256 MiB, which is 0.25 GiB. standard-1 has 4 GiB.

Wait, what? Re-pitch this lesson

Context. Our first scans hung. The cause was probably the container size.

Short version. The image is the recipe result, stored at Cloudflare. A container is one running copy. The default size has 256 MiB of memory. Claude Code needs more. We use standard-1 with 4 GiB.

Remember. Docker is only for the build. Size matters. "It worked after the change" is not the same as "we proved the cause".
