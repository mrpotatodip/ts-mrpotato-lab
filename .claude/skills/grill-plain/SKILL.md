Call the Skill tool with "grilling" and run its interview. Shape every question so it _lands_ on the first read, the way a `wait-what` re-pitch does:

- **Context**: open with one or two sentences on where the plan stands and why this decision matters now.
- **Words**: write in ASD-STE100 Simplified Technical English, with the ubiquitous language from `GLOSSARY.md` (follow `GLOSSARY-MAP.md` to the right one if the repo has more than one). Give each glossary term its meaning in a short clause the first time it appears.
- **Example**: show each option on one concrete case from this repo or the user's own plan ("if a cafe owner does X, then Y happens").
- **Picture**: draw the choice whenever it has shape: a flow, a before/after, a tree, a table. Use a small ASCII diagram or a `mermaid` block. A question about a pure preference or name needs none.

Each question ends on a choice the user answers in a few words, with your recommendation beside it.
